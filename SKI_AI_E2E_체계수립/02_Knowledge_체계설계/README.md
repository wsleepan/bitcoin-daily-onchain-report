## 2. 방법론의 4대 설계 원칙

체계가 백지 상태에서 시작하므로, "무엇을 먼저 정하느냐"가 성패를 가릅니다.
아래 4개 원칙이 이후 모든 Phase 순서의 근거입니다.

### 원칙 1. 활용에서 역산한다 (Use-Backward)
지식 구조화는 목적을 고정하지 않으면 무한히 확장되어 끝나지 않습니다.
`AI Agent 활용 시나리오 → 그 시나리오에 필요한 지식 → 그 지식의 구조·메타 요건`
순서로 역산하며, **활용 시나리오에 걸리지 않는 지식은 이번 범위에서 제외**합니다.
→ 그래서 Phase 1(현황 진단)에서 현업의 **실제 질의문 30~50건 수집**이 필수 산출물입니다.
   이 질의 목록이 Ontology 범위, 구조화 대상, LLM 데이터 요건의 공통 근거가 됩니다.

### 원칙 2. 표준은 빌려오고, CLX 특화만 새로 만든다 (Adopt–Adapt–Author)
참조 체계가 없는 상태에서 자체 표준을 창작하면 검증 근거가 없습니다.
외부 표준을 베이스라인으로 깔고, 항목별로 **채택(Adopt) / 수정(Adapt) / 신규(Author)** 를 판정합니다.
신규(Author) 항목에만 설계 공수를 집중합니다.

| 후보 표준 | 적용 영역 |
|---|---|
| Dublin Core (ISO 15836) | 문서 공통 메타데이터 15요소 — 공통 메타의 출발점 |
| SKOS | 통제어휘·동의어·상하위 관계 표현 방식 |
| ISO 30401 (지식경영시스템) | 지식 관리 거버넌스·R&R 프레임 |
| ISO 15489 (기록관리) | 생애주기·보존·폐기 기준 |
| 제조/공정 도메인 표준 (ISA-95, IEC 61512 등) | 설비·공정·배치 Entity 정의 |

### 원칙 3. 전수(全數)가 아니라 대표 유형 Pilot + 확장 가이드
전체 지식을 한 번에 다루면 3.5개월 안에 어떤 것도 완성되지 않습니다.
**대표 문서유형 3~5종**(OPeX, Tech Report, 근무일지 등)만 끝까지 실증하고,
나머지는 `Ontology 설계 및 확장 가이드`로 **일반화된 절차**를 넘깁니다.
→ 기대산출물의 "설계 및 확장 가이드"가 바로 이 원칙의 산출물입니다.

### 원칙 4. 사람이 입력하는 메타는 실패한다 (Automation-First)
메타데이터 표준의 성패는 항목 설계가 아니라 **입력 부담**에서 갈립니다.
모든 메타 요소에 `자동추출 가능여부`를 필수 컬럼으로 두고,
수기 입력 항목은 문서 양식에 내재화(생산 시점에 자연히 입력되는 구조)하거나 삭제합니다.
- 목표 기준: **필수 메타 중 자동추출·양식내재 비율 ≥ 60%**

## 3. "Ontology" 수준 정의 — 착수 즉시 합의 필요

본 과업의 Ontology는 **메타데이터 표준 중심의 실용적 지식 모델**로 정의합니다.
용어가 주는 기대와 실제 산출물 수준의 괴리가 이 과업 최대의 리스크이므로,
W1에 아래 표를 이해관계자와 명문화하고 시작합니다.

| 구분 | 본 과업 범위 (In) | 범위 외 (Out) |
|---|---|---|
| 분류체계 | 다면 Taxonomy 설계 (업무기능·설비/공정·문서유형·생애주기·보안등급) | — |
| 메타데이터 | 공통 필수 메타 + 문서유형별 확장 메타 표준 정의 | — |
| 통제어휘 | 설비·공정·제품 동의어/약어 정규화 사전 | 전사 전 도메인 용어 통합 |
| 관계 모델 | 경량 Entity–Relation (Entity 10~15, Relation 10 내외) | 형식 온톨로지(OWL/RDF) 추론 규칙 구현 |
| 구현 | 표준·가이드 문서, Hub 요건 정의 | 실제 Triple Store 구축, 그래프 DB 적재 |

## 6. 아직 정하지 못한 사항 (의사결정 필요)

착수 전/직후에 확정되어야 방법론이 완전히 고정됩니다.

1. **대표 문서유형 확정** — 기획서에 OPeX·Tech Report·근무일지가 예시로 있으나, 최종 선정은 Phase 1의 스코어링(T01) 결과로 결정
2. **지식 도메인 경계** — CLX 전체인지 특정 공장/공정 우선인지
3. **Knowledge Hub 구축 주체** — CLX 자체 / 전사 공통 플랫폼 활용 여부 (Phase 4 대안 범위가 달라짐)
4. **보안·반출 기준** — 도메인 LLM 학습 데이터의 사외 처리 가능 여부 (Phase 3B 확보방식 선택지를 좌우)
