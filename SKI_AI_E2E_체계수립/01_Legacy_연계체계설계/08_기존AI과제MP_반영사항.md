## 2. 대상 Legacy 재정의 — 3종 → 8종+

MP의 `Data Source` 장표에서 확인된 실제 시스템 목록입니다.

| 시스템 | 보유 데이터 | 성격 | 본 과업 우선순위 |
|---|---|---|---|
| **RTDB** | 실시간 공정 운전 Data, 공정 운전 실적, 공정 정보. **DCS 연동 (SP/OP/PV)** | 시계열 히스토리안 **(가정 확정)** | **1순위** |
| **OCEAN-H** | 정비 Schedule, 정비 이력, **근무일지 History**, 촉매 구매 이력 | EAM | **1순위** |
| **OASIS** | 생산/품질 실적, 생산 계획/실적 | 생산관리 | **1순위** |
| **AMS** | **실시간 공정 Alarm Data** | 알람 관리 | **2순위 — 신규 식별** |
| **PMS** | 공정 실적 Data, 특허 | 공정/성과 관리 | **2순위 — 신규 식별** |
| **TDMS** | **공정/설비 기본 정보** | 기술문서·마스터 | **2순위 — 신규 식별** |
| **DCS** | 공정 제어 (SP/OP/PV 원천) | 제어 시스템 | 3순위 (RTDB 경유 접근) |
| 투자관리 시스템 | 투자 사업 수행 문서 | 업무 시스템 | 4순위 |
| Teams | 생산 운영 정보, 투자 사업 정보 | 협업 도구 | 4순위 |
| 사고관리시스템 / 교육포탈 | SHE, 교육 이력 | 업무 시스템 | 4순위 |
| 외부 | 논문, 뉴스, 특허 | 외부 DB | 별도 (연계 방식·최신화 검토 필요) |
| 문서 자산 | 작업표준, S/U·S/D 절차서(Excel), **P&ID** | 비정형 | ② 범위 (일부 ① 접점) |
| **암묵지** | 상황별 운전 노하우, S/U·S/D 노하우 | 미축적 | **② + LKM 핵심** |

### 방법론 조정

**AMS(알람)의 발견이 가장 중요합니다.**
LKM 핵심 Point에 *"AMS – RTDB – 작업표준 연계한 상황 및 조치 DB화"* 가 명시돼 있습니다.
→ **P-MONITOR 패턴의 실제 원천은 RTDB가 아니라 AMS**입니다. 알람은 이미 이벤트 형태로 발생하므로, 내가 Phase 4에서 "이벤트 구독"으로 판정한 것의 구체적 대상이 AMS입니다.

**TDMS(공정/설비 기본 정보)는 식별자 표준의 제3 원천입니다.**
설비 마스터가 OCEAN-H에만 있다고 가정했으나, TDMS에도 공정·설비 기본 정보가 있습니다.
→ **Phase 3-2의 기준 원천 지정 시 OCEAN-H vs TDMS 중복·충돌을 먼저 확인**해야 합니다. 이것이 새로운 최우선 확인 사항입니다.

**Phase 0 활동 수정**
```
0-1 범위 기준선 확정
   기존: OCEAN·OASIS·RTDB 3종 + 추가 후보 선정 기준
   수정: 1순위 3종 확정 + 2순위 3종(AMS·PMS·TDMS) 편입 여부 판정
        + 마스터 중복(OCEAN-H vs TDMS) 확인을 선행 과제로 배치
```

## 4. LKM — 횡단 조인의 구체적 형태

MP의 **생산 LKM Concept**이 원칙 7(Join Key First)의 실증 대상입니다.

### 4-1. LKM 구조

> **정의**: Feed·설비·운전 변수 間 복잡한 상관관계를 바탕으로 공정 상태의 신속 진단 및 최적 조치를 가능하게 하는 지식 체계

```
   [상황]  ──→  [증상]  ──→  [조치]
     │            │            │
 공정 Alarm    근무일지      근무일지
 근무일지      DCS/RTDB      DCS/RTDB
 작업표준       (SP,OP)       (PV)
 암묵지        작업표준       암묵지
              암묵지
     └──────────┴────────────┘
      상황-증상-조치 연계 Data → Vector DB化
                    ↓
              생산 Agentic AI
     (공정 운전 Guide / 근무일지 작성 / 작업표준 제·개정)
```

### 4-2. ① 과업이 LKM에 기여해야 할 것

LKM은 본질적으로 **여러 Legacy를 시간·설비 축으로 조인한 결과물**입니다.
① 과업이 식별자 표준을 만들지 못하면 LKM은 성립하지 않습니다.

| LKM 요소 | 필요한 ① 산출물 | 없으면 |
|---|---|---|
| 상황 = 공정 Alarm | **AMS 연계 + Alarm↔공정 Tag 매핑** | 알람이 어느 설비인지 모름 |
| 증상 = DCS/RTDB (SP, OP, PV) | **태그↔설비↔물리량 매핑** | 값은 있으나 의미 없음 |
| 상황–증상 연계 | **시간축 표준** | 알람 시점과 공정값 시점이 안 맞음 |
| 증상–조치 연계 | **근무일지(OCEAN-H)↔설비↔시간** | 조치를 상황에 못 붙임 |
| 전체 | **설비 식별자(별칭 포함)** | 사람 질의를 시스템에 못 연결 |

> **MP 자체가 "Alarm-유관 공정 Tag 정보"를 Data List에 올려놓고 있습니다** (공정 이상 대응). 즉 이 매핑의 필요성은 이미 인식돼 있고, **① 과업이 그것을 표준으로 만드는 역할**입니다.

### 4-3. LKM 핵심 Point와 ①의 관계

| MP의 LKM 핵심 Point | ① 과업의 대응 |
|---|---|
| LKM 축적 대상 확보 — *AMS–RTDB–작업표준 연계한 상황·조치 DB화* | **Phase 3-2 횡단 식별자 표준** 이 선행 조건 |
| LKM 신뢰성 확보 — *AI Readable 기반 구축, 축적 Data와 운전 노하우 간 정합성* | **Phase 3 M2 업무 메타 + D5 신뢰 표시** |
| 운전 역량 확보 — 유사상황 Data 제공 | Phase 4 P-SEARCH 도구 설계 |
| 업무 역량 확보 — *Legacy DB 체계적 관리* | ① 과업 전체 |

> **"AI Readable 기반 구축"이 MP에 명시된 표현입니다.** 이것이 곧 본 방법론의 **Agent-ready Data 5대 요건(D1~D5)** 입니다. 용어를 MP에 맞춰 `AI Readable` 로 통일하면 조직 내 수용성이 높아집니다.

## 5. Tag Meta = ①과 ②의 공통 기반 ★

MP의 **Contents Meta 활용 온톨로지 연계** 장표가 결정적입니다.

> 목적: **Tag 별 파생되는 생산·설비·SHE 영역의 Data 연계**를 통하여 CLX 온톨로지 구축 대상 확대 및 LKM 강화

### 5-1. MP가 정의한 온톨로지 확대 2갈래

| 갈래 | 내용 | 소관 |
|---|---|---|
| **① 공장별 DCS/PMS 기반 공정·Tag별 Meta 정보 구성** | 공장 기준 Meta / 설비(Tag) Meta / 설비(Tag) 간 연결 정보 | **① Legacy 과업** |
| ② Contents Meta Frame | 문서 내 정보 추출 → Contents Meta 구조 대응 | **② Knowledge 과업** |

**MP가 정의한 Tag Meta 3계층**

| 계층 | 내용 |
|---|---|
| 공장 기준 Meta | 공정 정보(RHDS, HP 등) / 공정 단계(Reactor, 정제 단계 등) / 입출력 자원(입력자원, 출력제품) |
| **설비(Tag) Meta** | **Item No. / 설비 종류 / Tag명 / Tag 설명** |
| 설비(Tag) 간 연결 | 공정 / 공정 단계별 / 입출력 스트림 / **물질 Flow** |

### 5-2. 이것이 방법론에 미치는 영향 — 중요

**기존 방법론에서 나는 ①과 ②의 경계를 "정형 데이터 = ① / 비정형 문서 = ②"로 그었습니다. MP는 다르게 봅니다.**

MP에서 **Tag Meta는 온톨로지(②)의 발판**입니다. 즉:

```
   [① Legacy]                        [② Knowledge]
  Tag Meta 구성  ────연계 발판────→  CLX 온톨로지
  (설비·공정·물질Flow)                (Contents Meta Frame)
        │                                   │
        └────────── LKM 강화 ───────────────┘
```

**경계 재정의 (수정안)**

| 대상 | 소관 | 근거 |
|---|---|---|
| Tag·설비·공정 Meta 구성 | **① 주관**, ②에 제공 | 원천이 DCS/PMS/RTDB — Legacy 영역 |
| 설비(Tag) 간 연결 정보 (물질 Flow 등) | **① 주관** | 공정 구조 지식 |
| 온톨로지 상위 원칙·Entity/Relation | **② 주관**, ①의 Tag Meta를 입력으로 사용 | 지식 구조화 영역 |
| Contents Meta Frame (문서) | **② 주관** | 비정형 문서 |
| **근무일지** | **① 접근 경로(OCEAN-H)** + **② 텍스트 구조화** | 시스템은 ①, 내용은 ② |
| 작업표준 / P&ID | ② 주관, ①이 설비·Tag 연결 제공 | 문서이나 Tag와 강결합 |

> **이 경계표를 Phase 0-5(과업 경계 정의)에서 ② 담당과 합의하십시오.** 기존 방법론의 단순 경계(정형/비정형)로는 Tag Meta의 소관이 애매해집니다.

### 5-3. 산출물 조정

```
Phase 3-2 시스템 횡단 식별자 표준화
   추가 산출: "CLX Tag Meta 표준" — MP의 3계층 구조를 채택
             (공장 기준 Meta / 설비(Tag) Meta / Tag 간 연결 정보)
   ② 과업 인계: Tag Meta를 온톨로지 Entity 정의의 입력으로 제공
```

| 2단계 | '27~'28 | 확산·역량 강화 — **LKM 기반 Junior AI 구성원** | 활용 지식 범위 확대·품질 고도화 | ①의 산출물이 실행되는 단계 |
| 3단계 | '29~ | AI–구성원 협업체계 — **Process Group 단위 완결형 Senior AI 구성원** | 핵심 업무 간 연계 下 지식 축적 자동화 | Agent 간 연계(L5)가 필수화되는 시점 |

**MP 1단계 추진 방향성에 명시된 문구**
> *"도입 용이한 난이도 低 업무 우선 자동화"*, **"업무 활용 Data 단위 연계성 구축 要"**

→ **"Data 단위 연계성 구축"이 곧 ① 과업의 핵심 산출물(횡단 식별자 표준)입니다.** 착수보고에서 이 문구를 인용해 과업의 위치를 설명하면 가장 설득력이 있습니다.

### 6-1. Agent 간 연계(L5) 문서의 시점 조정

`07_Agent간_연계구조_및_기준.md` 에서 A2A 채택을 4단계로 미뤘는데, MP와 대조하면 근거가 더 분명해집니다.

| MP 단계 | Agent 형태 | 필요한 연계 수준 |
|---|---|---|
| 1단계 ('25~'26) | CLX AI Assistant (사용자 질의 응답) | L4 (도구 호출)로 충분 |
| 2단계 ('27~'28) | **Junior AI 구성원** — routine 업무 지원 | L4 + 초기 L5 (오케스트레이션) |
| 3단계 ('29~) | **Senior AI 구성원** — **Process Group 단위 업무 완결형** | **L5 필수** — 여러 도메인 Agent 협업 |

> **3단계의 "Process Group 단위 완결형 수행"이 곧 Agent 간 연계(P2 오케스트레이터–워커) 그 자체입니다.**
> ① 과업은 지금 **기준만 세우고 구조를 열어두면** 되며, 이 판단이 MP 로드맵과 정확히 일치합니다.

## 7. R&R 정합

MP에 역할 분담이 명시돼 있습니다.

| 조직 | MP상 역할 | ① 과업과의 관계 |
|---|---|---|
| **울산 CLX** | 업무別 Data List 제공 / AI 구성원 활용 피드백 / Work Redesign | **Phase 1·2의 주 협조 대상**. "업무別 Data List"가 이미 있다면 Phase 1 대폭 단축 |
| **DT 추진실** | AI 구성원 기능 제공 / Data 활용 환경 제공 / **실시간 데이터 연계** | **Phase 4의 주 협의 대상**. "실시간 데이터 연계"가 DT 추진실 소관 = RTDB/AMS 연계의 카운터파트 |

> **Phase 0-4(조사 기반 확보)에 "업무別 Data List" 확보를 최우선으로 넣으십시오.** MP상 울산CLX가 제공하기로 되어 있는 산출물이며, 존재한다면 Phase 1 인벤토리 작업의 상당 부분이 이미 되어 있는 것입니다.
